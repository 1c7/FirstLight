# 剂量计算公式

## 结论

这个 App 的剂量公式**必须和 Android/Flutter 姊妹项目保持完全一致**，1:1 照搬自 `light-for-better-sleep` 项目的 `lib/dose_calculator.dart`。公式背后的科学依据（ED50 半饱和锚点、剂量-反应曲线、强度和时长的互换关系）不在本文档重复，见姊妹项目的 [doc/1-为什么是1万lux.md](../../light-for-better-sleep/doc/1-为什么是1万lux.md) 和 [doc/4-每日剂量计算公式的科学依据.md](../../light-for-better-sleep/doc/4-每日剂量计算公式的科学依据.md)。

## 公式

对应实现见 `Sources/FirstLight/DoseCalculator.swift`：

- `weight(lux) = lux / (lux + 100)`（lux > 0 时；否则为 0）—— 100 lux 是已发表的 ED50 半饱和锚点
- `targetEffectiveMinutes = 20 * weight(10000)` —— 固定的每日目标，等价于"1万 lux 晒 20 分钟"的等效强光量
- `uselessBelowLux = 500` —— 低于这个 lux，光对生物钟基本没用，不计入累计
- 每次轮询 tick，只要当前 lux ≥ 500，就把 `weight(currentLux) * elapsedSeconds / 60` 加到今天的累计有效分钟数里（`elapsedSeconds` 封顶 10 秒，避免长时间没轮询把一大段算成一次样本）
- `remainingRealMinutes = (target - accumulated) / weight(currentLux)`，只在 currentLux ≥ 500 时才有意义
- 累计值 ≥ 目标值时算达标

## 和 Flutter 版的差异

Flutter 版有显式的"开始记录 / 停止"按钮，用户主动控制什么时候开始累计。这个 Mac 版**没有这个按钮**——只要 App 开着、光照有用，就一直在累计。原因是使用场景不同：Flutter 版是"专门拿出手机举起来晒"的主动会话式操作；Mac 版设计给"笔记本本来就开着放在旁边"的被动场景（比如带笔记本到户外坐着办公/看书），不需要用户专门开始一个"晒光会话"。

## 每日进度存储

累计的有效分钟数按日期存本地 JSON：

```
~/Library/Application Support/FirstLight/daily_effective_minutes.json
```

对应实现见 `Sources/FirstLight/DailyProgressStore.swift`，结构和 Flutter 版的 `daily_progress_store.dart` 类似：一个 `{日期: 累计分钟数}` 的字典，按日期分 key。纯本地，不联网、不需要账号、无埋点。
