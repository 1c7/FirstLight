# 项目结构与开发说明

## 从源码构建

README 只给普通用户看的"下载 dmg 装"这条路，这里是给想自己编译的人看的完整命令：

```sh
git clone <this repo>
cd FirstLight/app

# 打一个完整的 FirstLight.dmg（内部会先跑 build.sh）
./Packaging/make_dmg.sh
open FirstLight.dmg

# 或者只想本地跑一下、不装到"应用程序"里：
./Packaging/build.sh
open FirstLight.app
```

需要 Xcode Command Line Tools（提供 `swift`/`sips`/`iconutil`/`codesign` 这些命令）。

主窗口遵循“控制器 → 状态模型 → 视图”的单向依赖：控制器持有模型，模型把传感器
数据转换为展示字段，视图只观察模型。颜色和尺寸统一放在设计变量文件中，避免后续
调整界面时需要跨文件寻找魔法数字。详细边界见 `doc/4-本地化与界面架构.md`。

## 界面和交互

菜单栏标题始终显示实时 lux 数值。

- **左键点击**：打开（或关闭）主窗口，展示更大、更完整的信息——当前 lux、今日累计有效分钟 vs 目标（进度条）、达标/未达标状态、按当前亮度估算还需要多少分钟（光线太暗时显示"光线太暗，户外找个开阔地方"代替倒计时）。
- **右键点击**：打开包含“设置”“调试状态”和“退出”的菜单。设置页可以选择跟随
  系统、中文或英语。
- 关闭窗口（红色按钮）只是把窗口藏起来——App 本身继续在菜单栏后台运行、继续累计今天的剂量。这是靠 `AppDelegate` 里的 `applicationShouldTerminateAfterLastWindowClosed` 返回 `false` 保证的。

## App 图标

图标直接复用了 Android 姊妹项目的插画（`light-for-better-sleep/assets/icon/icon_adaptive_fg.png`）——推窗见光、伸手迎着太阳那张。选它是因为：

- 两个 App 是同一件事的两个平台，图标该是同一个视觉识别
- 这张图本来就是"内容居中、四周留透明边距"的构图（Android adaptive icon 的前景层），正好符合 macOS 图标的规范——macOS 从 Big Sur 起要求图标内容本身画在一个带边距的圆角方形里，不能像 iOS/Android 那样铺满整个画布，直接复用不用二次设计

`Packaging/icon_source_1024.png` 是这张图的本地副本（1024×1024，带 alpha 透明通道）。重新生成 `.icns` 的方法：

```sh
SRC="Packaging/icon_source_1024.png"
ICONSET="Packaging/AppIcon.iconset"
mkdir -p "$ICONSET"
sips -z 16 16     "$SRC" --out "$ICONSET/icon_16x16.png"
sips -z 32 32     "$SRC" --out "$ICONSET/icon_16x16@2x.png"
sips -z 32 32     "$SRC" --out "$ICONSET/icon_32x32.png"
sips -z 64 64     "$SRC" --out "$ICONSET/icon_32x32@2x.png"
sips -z 128 128   "$SRC" --out "$ICONSET/icon_128x128.png"
sips -z 256 256   "$SRC" --out "$ICONSET/icon_128x128@2x.png"
sips -z 256 256   "$SRC" --out "$ICONSET/icon_256x256.png"
sips -z 512 512   "$SRC" --out "$ICONSET/icon_256x256@2x.png"
sips -z 512 512   "$SRC" --out "$ICONSET/icon_512x512.png"
sips -z 1024 1024 "$SRC" --out "$ICONSET/icon_512x512@2x.png"
iconutil -c icns "$ICONSET" -o Packaging/AppIcon.icns
```

## 打包脚本做了什么

`Packaging/build.sh`：

1. `swift build -c release`
2. 把编译产物、`Packaging/Info.plist`、`Packaging/AppIcon.icns` 组装成 `FirstLight.app`
3. `codesign --force --deep --sign -` 做 ad-hoc 签名，让 Gatekeeper 不挡着不让在本机打开
4. `touch` 一下 bundle，让 Finder 别用旧的图标缓存

没有做公证（notarization），因为这个 App 目前不打算离开开发机分发。

`Packaging/make_dmg.sh` 在 `build.sh` 的基础上再包一层：把 `FirstLight.app` 和一个指向 `/Applications` 的快捷方式一起塞进一张 `FirstLight.dmg` 磁盘映像里，做成标准的"打开、拖进应用程序"安装体验，而不是让用户自己在项目目录里找 `.app` 运行。DMG 本身没有额外签名/公证，第一次在别的机器上打开还是会遇到 Gatekeeper 的"无法验证开发者"提示，右键选"打开"绕过一次即可，往后就正常了。

## 为什么不能加 App Sandbox

这个 App 故意**不带任何 sandbox entitlement** 构建。它需要在非沙盒环境下运行才能读到 `doc/1` 里说的那个 IOKit 传感器属性；如果以后加了 entitlements 文件（比如从某个开了 App Sandbox 的 Xcode 模板带过来的），传感器读取可能会**悄悄失效**，不会报错，只是数字不再更新——排查的时候容易漏掉这个原因。

这也是这个 App 没法上 Mac App Store 的直接原因：App Store 强制 App Sandbox，会挡掉 IOKit 访问。

## 开机自启动（可选，目前没做）

为了保持简单，没做开机自启动。想要的话，现代 API 是 `SMAppService.mainApp.register()`（macOS 13+），需要在 `AppDelegate.swift` 里加几行代码、菜单里加个勾选项——目前没接。
